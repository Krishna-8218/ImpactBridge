# 01 — Architecture & file layout

## The one idea

Eight people cannot integrate at the end. So **nothing is ever missing** — every API
route exists from hour one and returns realistic, schema-valid data. Backend work is
not "build the route", it is "delete the mock fallthrough on a route that already
works". Frontend never waits, never stubs, never writes a fetch by hand.

The Zod contract is the only place an endpoint's shape is written down. Types,
validation, mocks, the client, and the docs page are all derived from it, so they
cannot disagree.

## Dependency direction (enforced, not aspirational)

```
   src/contracts/  ← pure Zod + mock factories. Imports NOTHING from the app.
        ↑     ↑
        │     └────────────── src/lib/api-client.ts → used by every component
        │
   app/api/**/route.ts  → src/server/**  → src/db/**
                             (business logic)   (prisma)
```

Rules that make this hold:
- `src/contracts/**` may not import from `src/db`, `src/server`, or `react`. It must stay
  importable from both the client bundle and the server. This is what makes it safe as a
  shared source of truth.
- Components never import from `src/db` or `src/server`. They import `api` from
  `src/lib/api-client` and types from `src/contracts`.
- Route handlers contain **no business logic**. They call one function in `src/server/`.
  This is what makes a route swappable from mock to real without touching its file's shape.

## Why `src/contracts` and not `packages/contracts`

The user chose a single app over a monorepo (D4). A workspace package would have bought
one thing: the compiler refusing a bad import. We get ~90% of that from the dependency
rules above plus a lint rule, at zero configuration cost:

```js
// eslint.config.mjs — no-restricted-imports
{ patterns: [
  { group: ['**/db/*', '**/server/*'], message: 'Components must not import server code. Use src/lib/api-client.' },
]}
```

If the project outlives the hackathon, `src/contracts` lifts out into a package with no
code changes — that is the point of forbidding its inbound imports.

## Runtime notes (verified)

- Route Handler `context.params` is a **Promise** — always `await params` (V4).
- `RouteContext<'/items/[id]'>` is a global type helper in Next 16, generated by
  `next dev`/`next build`/`next typegen`. No import required.
- Node runtime everywhere. Do not set `export const runtime = 'edge'` — the Neon
  WebSocket driver and Better Auth are configured for Node here.
